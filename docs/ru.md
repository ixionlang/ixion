# Ixion: руководство для начинающих

Ixion — язык программирования со статической типизацией, который работает на JVM.
Он позволяет описывать данные через структуры, списки, кортежи и варианты `enum`,
а затем разбирать их с помощью `case`.

Это руководство рассчитано на читателя, который только начинает знакомство с
языком. Знание Kotlin или Java не требуется. Если программирование для вас тоже
новая тема, читайте разделы по порядку: каждый следующий использует предыдущие.

Руководство описывает реализованное ядро текущей рабочей версии компилятора.

## Подготовка и запуск

### Что понадобится

- JDK 21: комплект Java, в который входят команды `java` и `javac`.
- Git для получения исходников или распакованная копия репозитория.
- Любой текстовый редактор. Исходные файлы Ixion имеют расширение `.ix`.

Gradle отдельно устанавливать не нужно: в репозитории есть `gradlew` для macOS/Linux
и `gradlew.bat` для Windows. Первый запуск скачивает Gradle и зависимости проекта,
поэтому требует подключения к сети.

В терминале проверьте Java:

```sh
java -version
javac -version
```

Обе команды должны указывать на JDK 21. Если у вас установлено несколько JDK,
выберите 21 через `JAVA_HOME` и добавьте его каталог `bin` в `PATH`. Например,
для macOS/Linux, подставив настоящий путь к установленному JDK:

```sh
export JAVA_HOME="/path/to/jdk-21"
export PATH="$JAVA_HOME/bin:$PATH"
```

`/path/to/jdk-21` — обозначение для замены, а не готовый путь.

### Сборка компилятора

Откройте терминал в корне репозитория — в каталоге, где находятся `build.gradle`
и `gradlew` — и выполните:

```sh
./gradlew build
```

В PowerShell на Windows:

```powershell
.\gradlew.bat build
```

Сборка также запускает тесты. Отдельная команда проверки — `./gradlew test`.
Если в macOS/Linux оболочка сообщает `permission denied` для wrapper,
выполните `chmod +x gradlew` и повторите запуск.

### Запуск файла

Создайте в корне репозитория файл `hello.ix` с программой из следующего раздела.
Рядом с руководством есть вспомогательный [Gradle-скрипт](run-ixion.gradle),
который подключает компилятор вместе с его зависимостями:

```sh
./gradlew -q -I docs/run-ixion.gradle runIxion --args="hello.ix"
```

Аналогичная команда PowerShell:

```powershell
.\gradlew.bat -q -I docs/run-ixion.gradle runIxion --args="hello.ix"
```

Все команды ниже предполагают запуск из корня репозитория. Путь к программе
может быть относительным, например `examples/tutorial.ix`. Локальные модули
ищутся относительно корня проекта, из которого запущен компилятор.

### Режимы компилятора

По умолчанию Ixion создаёт JVM-байткод и запускает программу. Второй вариант
сначала генерирует Java, затем компилирует её через `javac` и запускает:

```sh
./gradlew -q -I docs/run-ixion.gradle runIxion --args="--java hello.ix"
```

| Аргумент | Действие |
| --- | --- |
| `--help` | Показать справку CLI |
| `--compile-only` | Создать байткод, не запускать программу |
| `--java` | Использовать генерацию Java |
| `--java --compile-only` | Только создать Java-исходники |
| `--optimize` | Включить существующие проходы оптимизации |

Результаты компиляции появляются в каталоге `.out` в корне проекта.
Обычный JAR из `build/libs` не содержит все зависимости и не настроен как
самостоятельный исполняемый дистрибутив. Для знакомства пользуйтесь командой выше.
Новые ADT и списки проверяются для JVM и Java; Go не является целью этого руководства.

## Первая программа

Скопируйте весь пример в `hello.ix`:

<!-- ixion-example: hello -->
```ixion
use <std>

def main() {
    std::println("Привет, Ixion!")
}
```

Вывод:

```text
Привет, Ixion!
```

`use <std>` подключает стандартный модуль. `def` объявляет функцию, а `main` —
точка входа: компилятор начинает выполнение с её тела между `{` и `}`.
`std::println` выводит значение и переходит на следующую строку.

Далее каждый пример с функцией `main` — самостоятельная программа. Заменяйте
содержимое файла целиком; несколько таких примеров не нужно склеивать в один файл.
Блок «Вывод» показывает вывод программы без служебных сообщений сборки.

## Как читать код

Вызов функции записывается как `имя(аргументы)`. Двойное двоеточие `::` отделяет
имя модуля или типа от имени функции или варианта. Точка `.` читает поле структуры.

Комментарии помогают объяснять код и не выполняются:

```text
// Комментарий до конца строки
/* Комментарий, который может занимать несколько строк */
```

Пишите каждый оператор с новой строки. Точки с запятой не нужны. Между аргументами,
параметрами, элементами списка, полями и ветвями `case` ставьте запятые.
В объявлениях полей, вариантах `enum` и ветвях `case` завершающая запятая допустима.
В литерале списка ставьте запятые только между элементами: `[1, 2, 3]`;
завершающая запятая списка пока не поддерживается парсером.

Регистр важен: `count` и `Count` — разные имена. В примерах типы называются
`Point`, `Task`, `Option`, а функции и переменные — `sum`, `task`, `count`.
Это соглашение оформления. Выбирайте имена, которые объясняют смысл данных.

## Значения и базовые типы

Значение — это конкретные данные: число `42`, строка `"текст"` или `true`.
Тип описывает, какие данные допустимы и какие действия с ними можно выполнять.
Проверка типов происходит до запуска программы.

| Тип | Примеры | Назначение |
| --- | --- | --- |
| `int` | `0`, `42`, `-7` | Целое 32-битное число |
| `float` | `1.5`, `1.5f` | Дробное число одинарной точности |
| `double` | `1.5d` | Дробное число двойной точности |
| `bool` | `true`, `false` | Логическое значение |
| `char` | `'A'` | Одна UTF-16 единица символа |
| `string` | `"Привет"` | Неизменяемый текст |
| `unit` | `()` | Единственное значение «нет полезного результата» |
| `never` | Нет значений | Вычисление не возвращает результат |
| `any` | Любое значение | Тип, скрывающий конкретный тип данных |

Для дробных чисел в учебных программах используйте десятичную точку:
`2.0f`, `2.0d`. `float` и `double` хранят приближения: не все десятичные дроби
представимы точно. Для переполнения `int` действуют правила JVM, поэтому язык
не обещает автоматического увеличения разрядности.

Аннотация `: тип` задаёт тип явно. Если её нет, компилятор выводит тип из значения:

<!-- ixion-example: basic-types -->
```ixion
use <std>

def main() {
    let count: int = 3
    let price: double = 2.5d
    let enabled: bool = true
    let letter: char = 'A'
    let title: string = "Ixion"
    let finished: unit = ()
    std::println(count)
    std::println(price)
    std::println(enabled)
    std::println(letter)
    std::println(title)
    std::println(finished)
}
```

Вывод:

```text
3
2.5
true
A
Ixion
()
```

Строки заключаются в двойные кавычки, `char` — в одинарные. `"A"` и `'A'`
имеют разные типы. В строках можно использовать `\n` для переноса строки,
`\t` для табуляции, `\"` для кавычки и `\\` для обратной косой черты.

Числа могут неявно расширяться в направлении `char → int → float → double`.
Обратное преобразование автоматически не выполняется. Из-за точности `float`
такое расширение не означает, что любое большое целое сохранится без округления.

`unit` удобно использовать как результат действия, например печати.
`void` пока принимается как другое имя `unit`; в новом коде используйте `unit`.
`never` нужен для функций, которые не возвращаются нормально, например `std::panic`.
В обычных прикладных объявлениях новичку он требуется редко.

## Привязки let и let mut

Привязка связывает имя со значением. `let` создаёт неизменяемую привязку.
Добавьте `mut`, если локальному имени нужно присваивать новые значения,
например при обновлении счётчика.

<!-- ixion-example: bindings -->
```ixion
use <std>

def main() {
    let step = 2
    let mut count = 1
    count = count + step
    count += 3
    std::println(count)
}
```

Вывод:

```text
6
```

Каждая привязка требует инициализатора. Значение может вычисляться при выполнении
программы, например вызовом функции.

`let mut` разрешает присвоить имени новое значение целиком. Поля структур и
элементы списков остаются неизменяемыми при обеих формах объявления. Параметры
функций, имена в шаблонах и переменная обхода `for` тоже неизменяемы.

Объявляйте рабочие значения внутри функций. Инициализация привязок на уровне
модуля ещё не завершена. На этом уровне доступен только `let` без `mut`.

При переносе старого кода замените объявления `const` на `let`, а объявления
`var` на `let mut`.

## Операторы и условия

Основные операции:

| Категория | Операторы |
| --- | --- |
| Арифметика | `+`, `-`, `*`, `/`, `%` |
| Сравнения чисел | `==`, `!=`, `<`, `<=`, `>`, `>=` |
| Логика | `!`, `&&`, `||`, `^` — XOR |
| Присваивание имени, объявленному через `let mut` | `=`, `+=`, `-=`, `*=`, `/=`, `%=` |
| Соединение строк | `+` |

`*`, `/`, `%` выполняются раньше `+` и `-`; скобки позволяют явно задать порядок.
Деление двух `int` отбрасывает дробную часть. Чтобы получить дробный результат,
используйте дробные операнды. Деление целого числа на ноль — авария выполнения.

Условие `if` должно иметь тип `bool`. Число или строка не превращаются в условие
автоматически. `else if` добавляет другую проверку, `else` — оставшийся случай.

<!-- ixion-example: conditions -->
```ixion
use <std>

def main() {
    let age = 20
    let hasTicket = true
    if age >= 18 && hasTicket {
        std::println("Вход разрешён")
    } else if age < 18 {
        std::println("Нужен сопровождающий")
    } else {
        std::println("Нужен билет")
    }
    std::println(7 / 2)
    std::println(7.0d / 2.0d)
    std::println((2 + 3) * 4)
}
```

Вывод:

```text
Вход разрешён
3
3.5
20
```

`&&` не вычисляет правую часть, если слева `false`; `||` — если слева `true`.
Это удобно для последовательных проверок. XOR `^` вычисляет оба аргумента.

`if` используется как оператор управления, а не как выражение для присваивания
результата. Для выбора значения можно написать функцию с `return` или `case`.
Сравнение целых и логических значений работает; строки удобно сравнивать через
`strings::equals`. Структурное `==` для списков, структур, кортежей и ADT
пока не реализовано.

## Функции

Функция объединяет действия, которые можно вызывать по имени.
После имени в скобках объявляются параметры, после `:` — тип результата.

<!-- ixion-example: functions -->
```ixion
use <std>

def add(left: int, right: int): int {
    return left + right
}

def greet(name: string): unit {
    std::println("Привет, " + name)
    return ()
}

def main() {
    greet("Маша")
    std::println(add(4, 5))
}
```

Вывод:

```text
Привет, Маша
9
```

`left` и `right` — параметры, а `4` и `5` при вызове — аргументы.
Число и типы аргументов должны соответствовать объявлению. Аргументы вычисляются
слева направо.

`return` завершает текущую функцию и отдаёт значение вызывающему коду.
У функции с полезным результатом каждый возможный нормально завершающийся путь
должен возвращать значение. Последнее выражение обычного тела функции не
заменяет `return`.

Если тип результата не указан, функция считается возвращающей `unit`, а не
выводит результат из последнего выражения. В такой функции допустимо закончить
тело без `return`. Для явного пустого возврата пишите `return ()`.
Не оставляйте одиночный `return`: следующая строка может стать его выражением.

Функции могут обращаться к другим функциям, объявленным ниже, и вызывать себя.
Рекурсия расходует стек; оптимизация хвостовых вызовов не обещается.

## Циклы

### While

`while` повторяет тело, пока условие истинно. Изменяйте данные так, чтобы цикл
мог завершиться:

<!-- ixion-example: while -->
```ixion
use <std>

def main() {
    let mut count = 0
    while count < 3 {
        std::println(count)
        count += 1
    }
}
```

Вывод:

```text
0
1
2
```

### For

`for имя : значение` последовательно обходит список или строку.

<!-- ixion-example: for -->
```ixion
use <std>

def main() {
    let mut total = 0
    for value : [2, 4, 6] {
        total += value
    }
    std::println(total)
    for letter : "ab" {
        std::println(letter)
    }
}
```

Вывод:

```text
12
a
b
```

При обходе строки переменная имеет тип `char`. Это UTF-16 единица, поэтому
некоторые символы, например эмодзи, занимают две позиции.

Список для `for` вычисляется один раз перед обходом. Присваивание исходному имени
другого списка внутри тела не меняет уже начатый обход. Переприсваивать само имя
элемента `for` нельзя. `break` и `continue` в учебном ядре не поддерживаются.
Для последовательностей чисел удобно сначала работать с явным списком;
не переносите диапазоны и формы циклов из других языков без проверки.

## Неизменяемые списки

Список содержит последовательность элементов одного типа. Тип списка целых —
`int[]`, списка строк — `string[]`, вложенного списка целых — `int[][]`.

<!-- ixion-example: lists -->
```ixion
use <std>

def main() {
    let original = [1, 2]
    let extended = std::append(original, 3)
    let joined = std::concat(extended, [4, 5])
    let empty: int[] = []
    std::println(original)
    std::println(extended)
    std::println(joined)
    std::println(std::len(empty))
}
```

Вывод:

```text
[1, 2]
[1, 2, 3]
[1, 2, 3, 4, 5]
0
```

`append` и `concat` возвращают новые списки. Старая версия сохраняется,
даже если на неё ссылаются несколько имён. Операций `push` и `pop` с изменением
исходного списка нет; компилятор предлагает перейти на неизменяемый API.

Для пустого `[]` нужен контекст, из которого известен тип элементов:
аннотация `let xs: int[] = []`, аргумент функции или явная специализация.
Запись `let xs = []` без такого контекста не подходит. Старая форма пустого
значения `int[]` не рекомендуется; `int[]` в новом коде — прежде всего запись типа.

Готовые списки инвариантны: `int[]` нельзя передать как `float[]` или `any[]`.
Отдельный литерал может получить ожидаемый тип `float[]` и расширить элементы
при создании: `let xs: float[] = [1, 2]`.

## Option: значение может отсутствовать

Обращение к элементу списка может не найти значение. `Option[T]` явно описывает
два исхода: `Option::Some(value)` содержит `T`, `Option::None` не содержит данных.
`Option` предопределён, отдельный импорт для него не требуется.

<!-- ixion-example: option -->
```ixion
use <std>

def valueOr(value: Option[int], fallback: int): int {
    return case value {
        Option::Some(number) => number,
        Option::None => fallback,
    }
}

def main() {
    let numbers = [10, 20]
    std::println(valueOr(numbers[0], -1))
    std::println(valueOr(numbers[2], -1))
    std::println(valueOr(std::get(numbers, -1), -1))
    let absent: Option[int] = Option::None
    std::println(valueOr(absent, 99))
}
```

Вывод:

```text
10
-1
-1
99
```

Индексы начинаются с нуля: у списка длины 2 допустимы 0 и 1.
`numbers[index]` означает то же, что `std::get(numbers, index)`, и имеет тип
`Option[int]`. Отрицательный индекс и выход за границы дают `None`.
Неявного извлечения значения нет: сначала обработайте `Some` и `None`.

Конструкция `case value { ... }` проверяет форму значения. В ветви
`Option::Some(number)` имя `number` связывается с содержимым `Some`.
Каждая ветвь заканчивается запятой. Подробнее шаблоны рассматриваются ниже.

`None` без данных не вызывают как функцию: пишите `Option::None`, а не
`Option::None()`. Если нет ожидаемого типа, укажите его явно:
`let absent = Option[int]::None`.

### Безопасное обновление

`std::updated` возвращает `Some` нового списка при допустимом индексе и `None`
за границами. Исходный список сохраняется в обоих случаях.

<!-- ixion-example: updated -->
```ixion
use <std>

def main() {
    let before = [1, 2, 3]
    let result = std::updated(before, 1, 20)
    case result {
        Option::Some(after) => std::println(after),
        Option::None => std::println("Индекс за границами"),
    }
    std::println(before)
}
```

Вывод:

```text
[1, 20, 3]
[1, 2, 3]
```

Для вложенного списка каждый уровень индексации тоже возвращает `Option`.
Сначала извлеките строку из `matrix[i]`, затем обработайте `row[j]`.
Запись `matrix[i][j]` без обработки промежуточного `Option` не подходит.

## Функциональные операции со списками

Вместо ручного цикла часто удобно описать преобразование функцией:

- `map` преобразует каждый элемент и возвращает список результатов.
- `filter` оставляет элементы, для которых проверка вернула `true`.
- `fold` накапливает один результат, начиная с заданного значения.

Здесь `lambda` создаёт небольшую функцию прямо в аргументе вызова.

<!-- ixion-example: functional-lists -->
```ixion
use <std>

def main() {
    let source = [1, 2, 3, 4]
    let doubled = std::map(source, lambda (value) { return value * 2 })
    let selected = std::filter(doubled, lambda (value) { return value > 4 })
    let total = std::fold(selected, 0, lambda (sum, value) { return sum + value })
    std::println(source)
    std::println(doubled)
    std::println(selected)
    std::println(total)
}
```

Вывод:

```text
[1, 2, 3, 4]
[2, 4, 6, 8]
[6, 8]
14
```

В `fold` первый параметр функции — текущий аккумулятор, второй — очередной элемент.
Для `selected = [6, 8]` вычисления идут так: `0 + 6`, затем `6 + 8`.

Все три операции вызывают функцию слева направо ровно один раз на элемент.
Пустой список не вызывает функцию; `fold` возвращает начальное значение.
`filter` сохраняет взаимный порядок оставшихся элементов.

| Вызов | Тип результата |
| --- | --- |
| `std::len(xs)` | `int` |
| `std::append(xs, value)` | `T[]` |
| `std::concat(xs, ys)` | `T[]` |
| `std::get(xs, index)` | `Option[T]` |
| `std::updated(xs, index, value)` | `Option[T[]]` |
| `std::map(xs, f)` | `B[]`, если `f` преобразует `A` в `B` |
| `std::filter(xs, predicate)` | `T[]` |
| `std::fold(xs, initial, f)` | Тип аккумулятора |


## Структуры и обновление with

Структура объединяет именованные поля. Например, точка содержит координаты `x` и `y`.

<!-- ixion-example: structs -->
```ixion
use <std>

type Point = struct {
    x: int,
    y: int,
}

def moveRight(point: Point): Point {
    return point with { x = point.x + 1 }
}

def main() {
    let original = Point(2, 5)
    let moved = moveRight(original)
    std::println(original.x)
    std::println(moved.x)
    std::println(moved.y)
}
```

Вывод:

```text
2
3
5
```

`Point(2, 5)` вызывает конструктор; аргументы идут в порядке объявления полей.
`point.x` читает поле. `with` создаёт новое значение, заменяя перечисленные поля
и сохраняя остальные. База вычисляется один раз, новые значения — по порядку записи.

Запись `point.x = 10` запрещена, в том числе если `point` объявлен через `let mut`.
При необходимости перепривяжите имя: `point = point with { x = 10 }`.

Структура подходит для данных, которые существуют одновременно: у точки есть
и `x`, и `y`. Для выбора одной из нескольких форм используется `enum`.

## Кортежи

Кортеж похож на небольшую структуру без имён полей. Он удобен для временного
возврата нескольких значений. Тип `(int, string)` содержит целое и строку.
Данные извлекаются шаблоном `case`.

<!-- ixion-example: tuples -->
```ixion
use <std>

def describe(): (int, string) {
    return (3, "элемента")
}

def main() {
    let pair = describe()
    case pair {
        (count, label) => {
            std::println(count)
            std::println(label)
        },
    }
    let single = (42,)
    std::println(case single { (value,) => value, })
}
```

Вывод:

```text
3
элемента
42
```

`(42)` — число в скобках, `(42,)` — одноэлементный кортеж, `()` — `unit`.
Для долгоживущих данных со смысловыми полями обычно понятнее структура.

## Enum: несколько форм одного типа

`enum` описывает закрытый набор вариантов. Каждый вариант может иметь собственные
данные. Такой тип называется алгебраическим типом данных, или ADT.

<!-- ixion-example: enum -->
```ixion
use <std>

type Delivery = enum {
    Pickup,
    Courier(address: string),
}

def destination(delivery: Delivery): string {
    return case delivery {
        Delivery::Pickup => "Самовывоз",
        Delivery::Courier(address) => address,
    }
}

def main() {
    std::println(destination(Delivery::Pickup))
    std::println(destination(Delivery::Courier("Лесная, 10")))
}
```

Вывод:

```text
Самовывоз
Лесная, 10
```

Значение `Delivery` находится ровно в одном варианте. У `Pickup` нет адреса,
поэтому невозможно случайно прочитать его в этой ветви. У `Courier` адрес обязателен.
Вариант без данных записывается без `()`, вариант с данными создаётся вызовом.

В отличие от структуры поля разных вариантов не читаются общим обращением
`delivery.address`. Сначала определите вариант через `case` и извлеките его поля.
`Option[T]` и `Result[T, E]` устроены по этому же принципу.

### Рекурсивные данные

Вариант может содержать значения своего же типа. Так описываются деревья:

<!-- ixion-example: recursive-adt -->
```ixion
use <std>

type Expr = enum {
    Number(value: int),
    Add(left: Expr, right: Expr),
}

def evaluate(expression: Expr): int {
    return case expression {
        Expr::Number(value) => value,
        Expr::Add(left, right) => evaluate(left) + evaluate(right),
    }
}

def main() {
    let expression = Expr::Add(Expr::Number(2), Expr::Number(3))
    std::println(evaluate(expression))
}
```

Вывод:

```text
5
```

Здесь `Expr::Add` хранит два подвыражения, а `evaluate` разбирает дерево рекурсивно.
Компилятор проверяет допустимость рекурсивных типов; рекурсия через аргументы
функциональных полей имеет дополнительные ограничения положительности.
Для начала используйте простые деревья через поля вариантов и списки.

## Case и шаблоны

`case` одновременно выбирает ветвь и может возвращать значение.
Проверяемое выражение вычисляется один раз. Ветви проверяются сверху вниз;
выполняется первая подходящая.

### Шаблоны

| Шаблон | Что означает |
| --- | --- |
| `_` | Любое значение без сохранения имени |
| `value` | Любое значение с привязкой имени `value` |
| `0`, `true`, `"ok"`, `()` | Конкретный литерал |
| `Option::Some(value)` | Вариант и его содержимое |
| `Point { x: x, y: y }` | Поля структуры |
| `(left, right)` | Компоненты кортежа |
| `[]` | Пустой список |
| `[first, second]` | Список ровно из двух элементов |
| `[first, ..rest]` | Непустой список и неизменяемый хвост |
| `int number` | Значение типа `int` и имя для него |

Шаблон `value` создаёт новое имя, а не сравнивает с ранее объявленной переменной.
Внутри одного шаблона нельзя привязать одно имя дважды. Привязки видны только
в своей ветви и неизменяемы. `..rest` или `.._` допустимы только в конце списка.

<!-- ixion-example: patterns -->
```ixion
use <std>

type Point = struct { x: int, y: int }

def firstOrZero(values: int[]): int {
    return case values {
        [] => 0,
        [first, .._] => first,
    }
}

def main() {
    let point = Point(4, 5)
    std::println(case point { Point { x: x, y: y } => x + y, })
    std::println(firstOrZero([7, 8]))
    std::println(firstOrZero([]))
    let value: Result[Option[int], string] = Result::Ok(Option::Some(12))
    std::println(case value {
        Result::Ok(Option::Some(number)) => number,
        Result::Ok(Option::None) => 0,
        Result::Err(_) => -1,
    })
}
```

Вывод:

```text
9
7
0
12
```

### Дополнительные условия: guards

После шаблона можно поставить `if` и логическое условие. Оно проверяется только
после успешного шаблона и может пользоваться извлечёнными именами.

<!-- ixion-example: guards -->
```ixion
use <std>

def classify(value: Option[int]): string {
    return case value {
        Option::Some(number) if number > 0 => "Положительное",
        Option::Some(_) => "Ноль или отрицательное",
        Option::None => "Отсутствует",
    }
}

def main() {
    std::println(classify(Option::Some(3)))
    std::println(classify(Option::Some(0)))
    std::println(classify(Option::None))
}
```

Вывод:

```text
Положительное
Ноль или отрицательное
Отсутствует
```

### Полнота и недостижимые ветви

Компилятор требует, чтобы `case` обработал все возможные значения.
Для `Option` обычно нужны `Some` и `None`. Для чисел, строк и `any` часто
нужна покрывающая ветвь `_` или привязка имени.

Guard не гарантирует покрытие: после `Some(x) if x > 0` остаются другие `Some`.
Даже `if true` не учитывается как безусловное покрытие. Нельзя поставить `_`
в начале, а затем добавлять другие ветви: они будут недостижимыми.

Анализ может попросить добавить покрывающую ветвь в особенно сложном случае.
Это проверка полноты, а не предложение молча проигнорировать данные:
выбирайте осмысленное действие для оставшихся значений.

### Блоки ветвей и return

Внутри ветви можно выполнить несколько действий. Последнее выражение блока
становится результатом ветви. У обычной функции это правило не заменяет `return`.

<!-- ixion-example: case-block -->
```ixion
use <std>

def doubleOrZero(value: Option[int]): int {
    let result = case value {
        Option::Some(number) => {
            std::println("Вычисляем")
            number * 2
        },
        Option::None => { return 0 },
    }
    return result
}

def main() {
    std::println(doubleOrZero(Option::Some(4)))
    std::println(doubleOrZero(Option::None))
}
```

Вывод:

```text
Вычисляем
8
0
```

`return` в ветви выходит из ближайшей функции или лямбды, а не только из `case`.
Пустой блок и блок, оканчивающийся присваиванием, дают `unit`.
Присваивание не является способом вернуть значение из ветви.

## Result: ожидаемые ошибки

`Result[T, E]` хранит успех `Result::Ok(value)` или ошибку `Result::Err(error)`.
Тип ошибки `E` выбираете вы: это может быть строка или собственный ADT.
В отличие от аварии выполнения, ошибка в `Result` остаётся обычным значением,
которое вызывающий код может обработать через `case`.

<!-- ixion-example: result -->
```ixion
use <std>

def divide(left: int, right: int): Result[int, string] {
    if right == 0 {
        return Result::Err("Нельзя делить на ноль")
    }
    return Result::Ok(left / right)
}

def show(result: Result[int, string]): unit {
    case result {
        Result::Ok(value) => std::println(value),
        Result::Err(message) => std::println(message),
    }
}

def main() {
    show(divide(10, 2))
    show(divide(10, 0))
}
```

Вывод:

```text
5
Нельзя делить на ноль
```

`Option` подходит, когда важно только наличие значения; `Result` — когда нужно
объяснить неуспех. Никакое автоматическое распространение ошибки через `?`
пока не предусмотрено: используйте `case`.

`std::panic("сообщение")` предназначен для аварийного завершения, а не для
обычного ожидаемого отказа. Если отсутствие данных — нормальная ситуация,
верните `Option`; если есть причина ошибки — `Result`.

## Обобщённые типы и функции

Обобщение, или generic, позволяет писать один тип или одну функцию для разных
типов данных. Параметр типа записывается в квадратных скобках после имени.

<!-- ixion-example: generics -->
```ixion
use <std>

type Box[T] = struct { value: T }
type Pair[A, B] = (A, B)
type UserName = string

def identity[T](value: T): T {
    return value
}

def wrap[T](value: T): Option[T] {
    return Option::Some(value)
}

def main() {
    let box: Box[int] = Box(42)
    let name: UserName = identity("Аня")
    let pair: Pair[int, string] = (box.value, name)
    std::println(identity[int](box.value))
    case pair { (number, text) => std::println(text), }
    std::println(case wrap(7) { Option::Some(value) => value, Option::None => 0, })
}
```

Вывод:

```text
42
Аня
7
```

`T`, `A`, `B` — имена параметров типа, а не ключевые слова.
`Box[int]` и `Box[string]` — разные конкретные типы. Число аргументов типа
должно совпадать с объявлением. Generic-параметры указываются после имени:
`type Box[T] = struct { ... }`, `def identity[T](...)`.

Часто компилятор выводит аргументы типов из данных или ожидаемого результата.
Если информации недостаточно, укажите тип явно, как у `Option[int]::None`.
Generic-функция должна работать для произвольного `T`: нельзя написать `value + 1`
для неограниченного `T`, считая, что при каждом вызове это окажется число.

`type UserName = string` создаёт alias — другое имя существующего типа.
Новая структура или `enum`, напротив, создают собственный номинальный тип:
две разные структуры с одинаковыми полями не становятся одним типом.

## Лямбды и функции как значения

Лямбда — функция без отдельного объявления `def`. Её можно сохранить и передать
другой функции. Тип `(int) => int` читается «функция из одного `int` в `int`»;
`(int, int) => int` принимает два аргумента, `() => int` — ни одного.

<!-- ixion-example: lambdas -->
```ixion
use <std>

def applyTwice(value: int, f: (int) => int): int {
    return f(f(value))
}

def main() {
    let increment: (int) => int = lambda (value) { return value + 1 }
    let double = lambda (value: int): int { return value * 2 }
    std::println(applyTwice(3, increment))
    std::println(double(4))
    std::println(std::map([1, 2], increment))
}
```

Вывод:

```text
5
8
[2, 3]
```

Типы параметров можно опускать, если известен ожидаемый функциональный тип,
например из аннотации или сигнатуры `map`. Результат лямбды также может выводиться.
Если контекста нет, укажите типы параметров явно. Как и у `def`, полезный результат
возвращается через `return`.

### Захват по значению

Лямбда может использовать имена снаружи, но захватывает их значения в момент
своего создания:

<!-- ixion-example: captures -->
```ixion
use <std>

def main() {
    let mut number = 1
    let read: () => int = lambda () { return number }
    number = 2
    std::println(number)
    std::println(read())
}
```

Вывод:

```text
2
1
```

Менять захваченное имя внутри лямбды нельзя. Если нужен локальный счётчик самой
лямбды, объявите его через `let mut` в её теле. Это правило помогает читать
преобразования списков: результат не зависит от незаметного изменения захваченных
привязок в процессе обхода.

## Объединения типов и any

Тип `int | string` означает «целое или строка». Разобрать конкретную альтернативу
можно типовым шаблоном. Для бизнес-моделей с собственным смыслом вариантов
обычно понятнее именованный `enum`.

<!-- ixion-example: unions -->
```ixion
use <std>

type Label = int | string

def describe(value: Label): string {
    return case value {
        int number => "Числовая метка",
        string text => text,
    }
}

def main() {
    std::println(describe(42))
    std::println(describe("Готово"))
    let hidden: any = Option::Some(5)
    std::println(case hidden {
        Option[int] value => case value { Option::Some(x) => x, Option::None => 0, },
        _ => -1,
    })
}
```

Вывод:

```text
Числовая метка
Готово
5
```

`any` принимает значение любого типа, но скрывает доступные операции.
Перед арифметикой или чтением полей нужно уточнить форму/тип через `case`.
Для `any` нужна покрывающая ветвь: набор из нескольких известных типов не
перечисляет все возможные значения.

Не используйте `any` вместо generic-параметра, если функция должна сохранить
тип входа в результате. В `identity[T](value: T): T` эта связь известна;
в функции с входом и выходом `any` — потеряна.

Сопоставление generic-объединений, альтернативы которых могут совпасть после
подстановки, например `T | int`, пока ограничено. Используйте отдельные варианты
своего `enum` либо покрывающий шаблон.

## Модули и несколько файлов

Модуль — отдельный исходный файл. `pub` делает объявление доступным извне,
а `use <путь>` подключает модуль. Последняя часть пути становится его квалификатором.

Создайте в корне проекта каталог `domain` и файл `domain/pricing.ix`:

<!-- ixion-module: domain/pricing -->
```ixion
pub type Price = struct { amount: int }

pub def addTax(price: Price): Price {
    return price with { amount = price.amount + 2 }
}
```

В `hello.ix` разместите:

<!-- ixion-example: modules -->
```ixion
use <std>
use <domain/pricing>

def main() {
    let price: pricing::Price = pricing::Price(10)
    let result = pricing::addTax(price)
    std::println(result.amount)
}
```

Вывод:

```text
12
```

Запускайте `hello.ix` из корня, где находится каталог `domain`.
`pricing::Price` — экспортированный тип и его конструктор,
`pricing::addTax` — экспортированная функция. Внутри модуля свои имена
используются без квалификатора.

Экспортированный `enum` открывает свои варианты: обращение имеет вид
`module::Type::Variant(...)`. Его тип с параметрами пишется `module::Type[int]`.
Публичная сигнатура не должна раскрывать приватный номинальный тип;
экспортируйте используемый тип через `pub type`.

Локальное имя, объявленное внутри блока, не видно после этого блока.
Переменные ветвей `case` тоже не выходят за свои ветви. Избегайте повторного
использования одинаковых имён без необходимости — так учебный код легче читать.

## Стандартные модули

### Std: вывод и работа с данными

`use <std>` подключает `std::print`, `std::println`, `std::len` и функциональный
API списков. `print` не добавляет перенос строки; `println` добавляет.
`len` поддерживает список и строку. Печатать можно любые значения, но представление
структур и ADT предназначено для диагностики, а не для сохранения данных в файл.

`std::readLine` присутствует в текущем runtime, но его nullable JVM-контракт ещё
не переведён на безопасный `Option`. Это не образец нового API; учебные программы
пока используют заранее заданные входные данные.

### Strings: преобразование текста

<!-- ixion-example: strings -->
```ixion
use <std>
use <strings>

def main() {
    std::println(strings::toUpperCase("hello"))
    std::println(strings::toLowerCase("IXION"))
    std::println(strings::toTitleCase("hello world"))
    std::println(strings::equals("ok", "ok"))
    std::println(std::len("abc"))
}
```

Вывод:

```text
HELLO
ixion
Hello World
true
3
```

Есть функции `toUpperCase`, `toLowerCase`, `toTitleCase` и `equals`.
Строки не меняются на месте. `toTitleCase` обрабатывает слова, разделённые пробелами;
не считайте её универсальным языковым редактором текста.

Строковая индексация пока сохраняет прежний контракт: `text[index]` возвращает
односимвольную строку и может аварийно завершиться за границами.
Она отличается от безопасной индексации **списков**, возвращающей `Option[T]`.
Проверяйте границы заранее или используйте `for` для последовательного обхода.

### Http: сетевые запросы

`use <http>` открывает функции модуля HTTP. Он вызывает внешнюю систему,
поэтому результат зависит от сети; такие вызовы не входят в воспроизводимые
учебные примеры выше.

| Функция | Аргументы | Результат |
| --- | --- | --- |
| `get`, `delete` | `url: string` | Тело ответа `string` |
| `post`, `put`, `patch` | `url: string, body: string` | Тело ответа `string` |
| `request` | `method: string, url: string, body: string` | Тело ответа `string` |
| `status` | `method: string, url: string, body: string` | HTTP-код `int` |
| `urlEncode` | `value: string` | Кодированная строка |

Например, вызов имеет вид `http::get("https://example.com")`.
Текущее имя функции статуса — `status`, а не `requestStatus` из старого руководства.
Модуль пока не оборачивает сетевые исключения в `Result` автоматически.

### Async: фоновые действия

`use <async>` предоставляет запуск лямбды в отдельном потоке.
`async::run` принимает лямбду без аргументов и возвращает идентификатор задачи `int`.
Для действия используйте лямбду с результатом `unit`.

| Функция | Действие |
| --- | --- |
| `run(task)` | Запустить действие в фоне |
| `runDelayed(delayMs, task)` | Запустить после задержки |
| `isRunning(taskId)` | Проверить, работает ли поток |
| `await(taskId)` | Дождаться завершения |
| `cancel(taskId)` | Запросить прерывание потока |
| `sleep(ms)` | Приостановить текущий поток |

Неизменяемые данные и захват по значению не превращают весь ввод-вывод в чистые
вычисления. Порядок вывода из разных потоков не фиксирован, а внешние ресурсы
требуют отдельной дисциплины. Изучайте async после обычных функций и лямбд.

## Учебный проект: список задач

Соберём несколько возможностей в одной программе. Задача содержит название
и состояние. Завершение задачи возвращает новую структуру, а завершение списка —
новый список. Поиск первого элемента учитывает возможность пустого списка.

<!-- ixion-example: tasks-project -->
```ixion
use <std>

type Status = enum { Open, Done, }
type Task = struct { title: string, status: Status }

def complete(task: Task): Task {
    return task with { status = Status::Done }
}

def isDone(task: Task): bool {
    return case task.status {
        Status::Open => false,
        Status::Done => true,
    }
}

def countDone(tasks: Task[]): int {
    return std::fold(tasks, 0, lambda (count, task) {
        return count + case task.status {
            Status::Open => 0,
            Status::Done => 1,
        }
    })
}

def firstTitle(tasks: Task[]): Option[string] {
    return case tasks[0] {
        Option::Some(task) => Option::Some(task.title),
        Option::None => Option::None,
    }
}

def main() {
    let tasks = [
        Task("Изучить let", Status::Done),
        Task("Разобраться с case", Status::Open)
    ]
    let completed = std::map(tasks, lambda (task) { return complete(task) })
    std::println(countDone(tasks))
    std::println(countDone(completed))
    std::println(std::len(std::filter(tasks, lambda (task) { return isDone(task) })))
    std::println(case firstTitle(tasks) {
        Option::Some(title) => title,
        Option::None => "Задач пока нет",
    })
}
```

Вывод:

```text
1
2
1
Изучить let
```

Обратите внимание на `tasks` и `completed`: старые данные остались доступными.
Состояние задачи разбирается через варианты, а отсутствие первой задачи — через
`Option`. Изменение данных выражено возвращаемыми значениями функций.

## Частые ошибки

### Переприсваивание неизменяемой привязки

Если нужно переприсваивание, объявите локальную привязку через `let mut`.
Чтобы обновить поле структуры или элемент списка, создайте новое значение.

### «Не удаётся вывести тип»

Частые причины — пустой список и вариант без данных. Добавьте контекст:

```text
let values: int[] = []
let absent: Option[int] = Option::None
let another = Option[string]::None
```

Не заменяйте неизвестный тип на `any` автоматически: так легко потерять полезные
проверки и перенести ошибку на последующую обработку.

### «Case не покрывает все значения»

Добавьте пропущенный вариант. Для `Option` проверьте наличие `None`, для списков —
пустого `[]`. Если есть guard, добавьте ветвь без него для остальных значений.
Диагностика `match.non_exhaustive` может показывать пример пропущенного шаблона.

### «Недостижимая ветвь»

Уберите повторный шаблон или перенесите широкую ветвь `_` вниз.
Проверка `match.unreachable` означает, что предыдущие ветви уже покрывают эту область.

### «Ожидался int, получен Option[int]»

Индексация списка не возвращает элемент напрямую. Разберите результат через
`case`, как в разделе `Option`. Аналогично `updated` возвращает `Option[T[]]`.

### «Функция не всегда возвращает значение»

Проверьте каждый путь `if`/`else`. Используйте `return выражение`;
последнее выражение обычного тела функции не считается возвратом.
Для функции-действия можно выбрать результат `unit`.

### «Готовый int[] не подходит вместо float[]»

Параметризованные данные инвариантны. При необходимости создайте новый список
через `map` с ожидаемым результатом, например специализацию `std::map[int, float]`.
Не путайте преобразование нового литерала с переинтерпретацией готового списка.

### Ошибки запуска

- `Unsupported class file` или несовместимость Gradle/JDK: проверьте `JAVA_HOME`
  и запустите сборку на JDK 21.
- `ClassNotFoundException` при самостоятельном запуске JAR: используйте
  документационный Gradle-скрипт, который собирает runtime classpath.
- Файл или модуль не найден: проверьте текущий каталог, регистр имён и путь
  `use <domain/pricing>` относительно корня проекта.
- Непонятная ошибка разбора: проверьте запятые, парность скобок и наличие выражения
  после `return`.

При сообщении об ошибке сохраняйте минимальный исходник, полный текст диагностики,
версию JDK и команду запуска. Это помогает отличить ошибку программы от ограничения
или дефекта компилятора.

## Ограничения текущей версии

Реализованы JVM- и Java-исполнение нового ядра, неизменяемые произведения и списки,
generic/рекурсивные ADT, `Option`/`Result`, вложенные шаблоны, guards и проверка полноты.
При этом работа над целевой редакцией продолжается:

- Структурное равенство и хеширование данных ещё не реализованы. Не используйте
  `==` для структур, ADT, кортежей и списков; извлекайте нужные поля и сравнивайте их.
- Полная инициализация верхнеуровневых привязок ещё не завершена. Держите рабочие
  значения внутри функций.
- Универсальные адаптеры nullable/изменяемых JVM-объектов и внешних ресурсов
  остаются в плане. Гарантии новых списков не распространяются на произвольный
  внешний объект, который можно получить из старого native API.
- Различающее сопоставление потенциально совпадающих generic-unions ограничено
  диагностикой `pattern.overlapping_generic_union`.
- У Java-генератора остаётся ограничение некоторых `case`-блоков: возврат имени
  локальной константы, объявленной в этом же блоке, последним выражением может
  привести к ошибке сгенерированного Java. До исправления вычисляйте итоговое
  выражение напрямую, как в примере блока ветви выше.
- Часть старого синтаксиса ещё принимается для миграции. Новому коду стоит следовать
  формам из этого руководства. Диапазоны `..` и возведение в степень `**` из целевой
  спецификации не входят в проверенный набор операций этого учебника.
- Нет обещания полноценной поддержки Go, оптимизации хвостовой рекурсии,
  автоматического `?`, классов типов, GADT, изменяемых builders, Map/Set и
  гарантированной сложности persistent-коллекций.

Полное текущее состояние фиксируется в [статусе реализации](../spec/implementation-status.md).
Этот раздел помогает выбрать доступную конструкцию, пока язык развивается.

## Упражнения и памятка

### Попробуйте самостоятельно

1. Измените первую программу так, чтобы она вывела две строки: имя и приветствие.
2. Напишите `max(left: int, right: int): int`, возвращающую большее число через `if`.
3. Посчитайте сумму списка циклом, затем перепишите решение через `fold`.
4. Напишите `last(values: int[]): Option[int]`, используя `len` и безопасную индексацию.
5. Создайте `Rectangle` с шириной и высотой; напишите функцию, возвращающую новую
   структуру с увеличенной шириной через `with`.
6. Добавьте к дереву `Expr` вариант умножения. Обновите `evaluate` и посмотрите,
   какую диагностику выдаёт компилятор, если забыть новую ветвь.
7. Напишите `firstPositive(values: int[]): Option[int]` через рекурсивные шаблоны
   `[]` и `[first, ..rest]`.
8. Измените учебный проект: добавьте вариант `Status::Cancelled` и явно определите,
   как его обрабатывают `complete`, `isDone` и `countDone`.

### Короткая памятка

| Задача | Форма |
| --- | --- |
| Сохранить значение | `let name = value` |
| Переприсваивать локальное имя | `let mut count = 0` |
| Объявить функцию | `def f(value: int): int { return value }` |
| Объявить структуру | `type Point = struct { x: int, y: int }` |
| Обновить структуру | `point with { x = 10 }` |
| Объявить варианты | `type State = enum { Idle, Busy(value: int), }` |
| Представить отсутствие | `Option[T]` |
| Представить ожидаемую ошибку | `Result[T, E]` |
| Прочитать элемент списка | `values[index]`, затем `case` |
| Вернуть функцию как значение | `lambda (x: int): int { return x + 1 }` |
| Подключить модуль | `use <domain/pricing>` |
| Экспортировать объявление | `pub def ...`, `pub type ...` |

Для дальнейшего чтения: [ADT и сопоставление](adt.ru.md),
[подробности списков](lists.ru.md), [целевая спецификация](../spec/specification.ru.md).
